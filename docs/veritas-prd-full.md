# Veritas 教师后台产品需求与复刻说明（完整 PRD）

> 来源：Patrick 用 Codex 采集的参考后台完整产品文档，2026-09-25。
> 性质：产品结构 + 业务规则参考，不含真实学生姓名、手机号、成绩、班级名单或账号信息。
> 配套：`docs/veritas-backend-blueprint.md`（本项目的落地蓝图，做了范围裁剪）。

## 1. 产品定位

面向培训机构教师的教学管理后台，把学员管理、班级管理、排课、题库、作业布置、答题结果、批改反馈、学习报告整合到一套系统。使用者：任课教师、班主任、教研人员、机构管理员；学生/家长通过另一端接收课程、完成作业、查看结果与反馈。

核心业务闭环：
1. 机构建立学员档案并把学员加入班级。
2. 教师从题库、作业大纲或自定义内容选择任务。
3. 教师向班级布置普通作业、模考、打卡任务或视频课件。
4. 学生完成并提交，系统自动统计客观题结果。
5. 教师查看完成、批改、成绩、错题和答题过程。
6. 系统生成班级统计、学习报告、异常提醒和待办。

## 2. 一级信息架构

固定左侧导航：

| 一级模块 | 主要职责 |
|---|---|
| 首页 | AI 助手、待办、异常预警、公告、数据看板 |
| 学员 | 学员搜索、档案、班级关系、学习数据、考试记录 |
| 班级 | 班级筛选、成员、作业、课表、反馈、大纲、概览 |
| 作业 | 作业布置、管理、批改、收藏、统计、结果查看 |
| 课表 | 月历、课程、请假、教室、线上课安排 |
| 题库 | 按学科、机构、来源、分项检索教学内容 |
| 教研 | 作业大纲、知识点、目录结构维护 |
| 云盘 | 私有文件、共享文件、上传、容量管理 |
| 申请 | 排课申请、状态跟踪、处理结果 |

全局顶栏：搜索、消息通知、帮助/功能入口、账户信息、带数量角标的提醒入口。

## 3. 首页

顶部页签：AI 助手 / 待办事项 / 黑板报 / 数据看板。

待办和异常按可执行任务组织提醒：
- 待布置作业（班级数量 + 科目 + 教师负责分项）
- 待反馈（学生数量 + 所属课程）
- 学生作业异常（连续未提交）
- 课程班作业异常（完成率低）
- 新功能/机构公告

数据看板建议：今日课程、待批改数、待反馈数、作业完成率、异常学生数、近期成绩趋势。

## 4. 学员模块

左侧学员列表：总数、按班级筛选、关键词搜索（姓名 + 手机号）、头像/姓名缩写 + 姓名 + 班级数量；选中后在右侧显示完整档案。

详情页签：信息 / 课表和任务 / 学习报告 / 练习情况 / 课程反馈 / 考试记录。

基础档案字段：姓名、性别、出生日期、城市、手机号（默认脱敏）、微信号、微信昵称、顾问、年级、学校、专业、账号截止时间、学生公众号关注状态、家长公众号关注状态。

班级关系：一名学员可加入多班级，关系记录保存班级状态、课程名称、开课日期、在读状态。

考试记录字段：测试日期、测试题目、测试状态、做题时长、测试分数、查看详情。

## 5. 班级模块

列表筛选：科目、班级类型、状态、全部班级。卡片显示班级名称 + 科目。班级类型覆盖一对一/一对多/常规班/集训班/冲刺班/试听班/打卡班/机构专用班等可配置类型。

详情头部：班级名称、开课状态、开课日期、课程进度（已完成/总课时）、成员数、任课教师 + 班主任。

详情页签：作业 / 课表 / 反馈 / 作业大纲 / 概览。

右侧快捷功能：成员管理、布置作业（模考作业/自定义作业/打卡作业）、其他作业（常用作业/视频课件）。

## 6. 作业模块

### 6.1 作业中心栏目
布置作业 / 全部作业 / 单词作业 / 打卡作业 / 作业模考 / 视频课件 / 实时作业 / 未下发作业 / 我的批改 / 我布置的 / 收藏作业。栏目名旁显示数量。

### 6.2 筛选
科目（全部/托福/SAT/雅思/其他/SSAT/小托福等）、状态（未开始/进行中/已完成/已逾期）、批改状态（未批改/部分批改/已批改）、查阅状态（未查阅/部分查阅/已查阅）、班级、起止时间、排序、重置。

### 6.3 作业卡片字段
作业类型、状态、名称+试卷/模块名、起止时间、班级、布置老师、批改老师、题目数、平均成绩、完成数/应完成、批改数/应批改。操作：AI 作业分析、预览、查看。

### 6.4 结果详情
参与学生 / 题目 / 统计 / 排行榜。打卡类显示当天打卡率 + 已打卡人数。普通/模考显示学生提交状态、成绩、批改状态、查阅状态。

答案解析页建议：学生列表及完成状态、学生答案、正确答案、对错标记、错误归因、知识点、选项分布、单题详情、作答录屏/答题过程、教师评语、PDF 报告导出。

### 6.5 作业状态机（四组独立，勿合并）

作业生命周期：`草稿 → 未下发 → 未开始 → 进行中 → 已完成/已逾期`
提交维度：`未提交 → 已提交`
教师批改维度：`未批改 → 部分批改 → 已批改`
教师查阅维度：`未查阅 → 部分查阅 → 已查阅`

## 7. 课表模块

月历视图，当前年月、快捷返回、课时详情入口。事件展示班级/课程名、教学分项、本班第几次课、上课方式、校区教室、起止时间。支持请假（日期、时间段、原因、申请状态、审批结果）。建议月/周/日三视图，按教师/班级/校区/教室筛选。

## 8. 题库模块

筛选：学科、机构、单词书、科目、分项、来源、名称、筛选、排序、重置。最小数据单位为题目，可归属试卷、模块、文章、知识点、来源。支持单题、多题组、阅读文章+多题、数学公式、图片、音频、视频。

## 9. 教研模块

作业大纲 / 知识点 两个页签。作业大纲按科目建层级目录：创建大纲、添加分类、创建任务/目录项、拖拽排序、显示上传人、显示应用次数、编辑操作。大纲可被班级关联复用。

## 10. 云盘模块

我的云盘 / 共享云盘。功能：上传、容量配额+已用、搜索、文件名、大小、上传日期、操作、分页。共享云盘需文件夹权限、机构范围、教师范围、只读/可编辑权限。

## 11. 申请模块

核心是排课申请。筛选：班级、状态。字段：校区、班级、申请人、申请时间、备注、状态、已排/总课时、处理人、驳回原因、操作。状态机：`待处理 → 已通过/已驳回 → 排课中 → 已完成`。

## 12. 核心数据模型

### 12.1 用户和权限
users、roles、permissions、user_roles、organizations、campuses、teacher_profiles、student_profiles、parent_profiles

### 12.2 教学组织
subjects、courses、classes、class_members、class_teachers、classrooms、schedules、leave_requests、scheduling_requests

### 12.3 内容和题库
question_banks、passages、questions、question_options、knowledge_points、question_knowledge_points、papers、paper_sections、paper_questions、vocabulary_books、files

### 12.4 作业和答题
assignments、assignment_targets、assignment_questions、submissions、submission_answers、grading_records、teacher_comments、error_attributions、answer_recordings、assignment_statistics

### 12.5 教研和反馈
syllabuses、syllabus_categories、syllabus_items、course_feedback、learning_reports、notifications、todo_items、anomaly_events

业务表建议含 organization_id（多机构隔离）；关键记录含 created_by / updated_by / created_at / updated_at / deleted_at。

## 13. 角色和权限

- 机构管理员：管理校区、教师、学员、班级、权限、共享资源、全机构数据。
- 班主任：管理自己班级、成员、作业、课程反馈、家长沟通。
- 任课教师：查看负责班级和学员，用题库，布置作业，批改反馈。
- 教研人员：维护题库、知识点、试卷、作业大纲、共享资源。
- 学生/家长：只访问本人或绑定学生的课程、作业、成绩、反馈。

权限必须同时考虑角色、机构、校区、班级、数据归属，不能只做前端菜单隐藏。

## 14. 建议 API 分组

`/auth/*`、`/students/*`、`/classes/*`、`/schedules/*`、`/questions/*`、`/assignments/*`、`/submissions/*`、`/reports/*`、`/syllabuses/*`、`/files/*`、`/requests/*`、`/notifications/*`

## 15. 第一阶段 MVP

1. 登录、组织、角色和权限
2. 学员档案、班级和班级成员
3. 题库、试卷和知识点
4. 作业创建、发布、学生答题、自动判分
5. 教师作业管理、答题结果和评语
6. 班级统计、个人学习报告、异常提醒
7. 课表与排课

第二阶段：AI 作业分析、录屏回放、云盘、教研大纲、复杂审批、公众号通知。

## 16. 非功能要求

- 多租户数据隔离，任何查询校验 organization_id。
- 学生手机号默认脱敏，授权角色才看完整值。
- 成绩、评语、批改、权限变更记录审计日志。
- 大列表服务端分页、筛选、排序。
- 作业统计异步任务预计算，避免实时扫全量。
- 上传文件类型、大小、病毒检查。
- 删除用软删除 + 回收/恢复。
- 导出报告记录导出人、时间、范围。
- 桌面端优先响应式布局，学生答题端另做移动端。

## 17. 交给开发 AI 的提示词（原文）

> 请根据本文档设计并实现一个教育机构教师管理后台。产品采用多租户架构，核心对象为机构、校区、教师、学员、家长、课程、班级、课表、题库、知识点、试卷、作业、提交、答案、批改、评语、报告和排课申请。先输出完整 PRD、页面路由、角色权限矩阵、ER 图和 API 契约，再开始编码。
>
> 第一版必须完成登录与权限、学员、班级、题库、作业、答题结果、批改、统计报告和课表闭环。后台采用固定左侧一级导航和顶部全局工具栏，列表页统一支持搜索、筛选、排序、分页和空状态。详情页使用页签组织复杂信息。
>
> 请特别注意：作业生命周期、学生提交状态、教师批改状态和教师查阅状态是四组独立状态，不要合并成一个字段；所有业务记录必须带机构隔离字段；学生手机号默认脱敏；批改、成绩、评语和权限变更必须有审计日志。不要复制任何第三方品牌、Logo、真实学生数据或专有题目内容，只实现同类业务能力和原创界面。
>
> 在编码前请先向我确认技术栈。如果没有指定，建议采用 Next.js + TypeScript + Tailwind CSS + shadcn/ui，后端采用 NestJS 或 Next.js API，数据库采用 PostgreSQL + Prisma，文件使用兼容 S3 的对象存储，任务队列采用 Redis + BullMQ。为每个模块提供种子数据、权限测试和核心端到端测试。

## 18. 后续可继续采集

每一种作业的创建向导和必填字段、题库题目编辑器及各题型结构、模考答题解析/录屏/报告导出页面、数据看板全部指标和图表、班级反馈编辑器及家长端展示、角色权限配置页面、排课冲突/审批/通知规则、学生端和家长端完整流程。
